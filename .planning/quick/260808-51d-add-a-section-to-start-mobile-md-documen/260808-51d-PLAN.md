Append a new top-level section to the end of `start_mobile.md`, heading `## 6. Remote Contributor Testing Over An ngrok Tunnel`. Write it in the file's existing voice: short declarative sentences, imperative steps, concrete commands. Cover six subsections in this order.

Intro paragraph (no subsection heading, directly under the `## 6.` heading) — state when to use this instead of sections 1-4. The distinguishing condition is that the contributor is on a **different network entirely**: not plugged into this PC by USB, and not on the same Wi-Fi, so neither `adb reverse` (section 3) nor the PC LAN IP fallback (last bullet of the existing Troubleshooting section) can reach the backend. An ngrok tunnel gives the local backend on port `5059` a public HTTPS URL any network can call. Add one sentence saying sections 1-4 remain the right choice when the device is on your desk or your Wi-Fi, since they are faster and involve no third-party service.

`### 6.1 Install ngrok (One Time, On Your PC)` — note ngrok is already installed on this machine, then give `winget install ngrok.ngrok` in a powershell block for anyone setting up fresh. Then say: create a free ngrok account, copy the authtoken from the ngrok dashboard, and register it once with `ngrok config add-authtoken <your-authtoken>` in its own powershell block. Note the authtoken is stored in ngrok's own config and is registered once per machine, not per session.

`### 6.2 Start The Local Backend` — do not restate the dotnet command. Point at section 2 above and say the tunnel forwards to that same already-running process on port `5059`; there is no second backend to start, and that terminal stays open.

`### 6.3 Open The Tunnel` — in a second terminal (alongside the section 2 backend terminal), run `ngrok http 5059` in a powershell block. Then show the Forwarding line ngrok prints, in a text block, in the shape `Forwarding    https://<subdomain>.ngrok-free.app -> http://localhost:5059`. Instruct the reader to copy the https URL and keep this terminal open for the whole session, because closing it tears down the tunnel.

`### 6.4 What To Send The Contributor` — lead with the rule that these all travel over a private channel (direct message, encrypted file, password-manager share) and never through git; every item below is on the do-not-commit list in `docs/CONFIGURATION.md`. Then a bullet list of exactly three items: (a) the current ngrok https URL from 6.3; (b) the values from `mobile/env.json` — `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `GOOGLE_SERVER_CLIENT_ID` — so the contributor can write their own `mobile/env.json`, since that file is gitignored and is not present in a fresh clone; (c) `mobile/android/app/google-services.json`, only if they need to test FCM push (section 5.5) — also gitignored and absent from a fresh clone, so skip it when push is not being tested.

`### 6.5 The Contributor's Run Command` — the contributor clones the repo, writes their own `mobile/env.json` from the values in 6.4, then runs from their `mobile` directory. Give the command in a powershell block, substituting the ngrok https URL for the IP that sections 4 and 5.3 use: `flutter run --dart-define-from-file=env.json --dart-define=API_BASE_URL=https://<subdomain>.ngrok-free.app`. Add a sentence noting they need no `adb reverse` and no `-d <device-id>` from this repo's device list — their phone or emulator is attached to their own machine, and the API URL is public rather than loopback.

`### 6.6 Free-Tier URLs Change Every Session` — on the free tier ngrok assigns a new random subdomain every time the tunnel restarts, so the previously-sent URL goes dead. Each restart means: copy the new https URL from the Forwarding line, re-send it, and have the contributor re-run with the new `--dart-define=API_BASE_URL`. Contrast this with a paid ngrok plan's reserved domain, which stays stable so the contributor can save the run command once.
