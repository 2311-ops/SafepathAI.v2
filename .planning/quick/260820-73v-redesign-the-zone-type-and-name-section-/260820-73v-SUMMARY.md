# Quick Task 260820-73v: Redesign Zone Type & Name Section Summary

**Replaced the plain-text "ZONE TYPE AND NAME" label + ChoiceChip Wrap + raw TextField in SafeZoneEditorScreen with an icon-led, category-colored `_CategoryAndNamePanel` card matching `_LocationPickerPanel`'s exact visual language, plus a `SafePathTextField` name input with a category-matched prefix icon.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2/2 completed
- **Files modified:** 2 (`edit_safe_zone_screen.dart`, `safe_zone_editor_test.dart`)

## Accomplishments

- `_CategoryAndNamePanel` card added: surface-colored `DecoratedBox` (18px radius, hairline border, single soft `BoxShadow`) with an icon+title+subtitle header row, mirroring `_LocationPickerPanel` exactly.
- `_CategoryOption` chip widget: icon-led, category-colored (home=safe green, school/university=teal, workplace=violet, custom=slate), 12%-alpha tint + border when unselected, solid color + shadow + white check icon when selected, 44x44 minimum touch target, 180ms `AnimatedContainer` transition.
- `_categoryColor`/`_categoryIcon` top-level helpers added, copied from `safe_zones_screen.dart`'s private functions of the same name (originals can't be imported across files since they're private).
- Raw `TextField` replaced with the shared `SafePathTextField` widget, showing the selected category's icon as `prefixIcon`.
- All existing behavior preserved unchanged: `controller.selectCategory(category)` → `_nameController.text = controller.draft.name` sync, and `controller.setName` on name change.
- No `AppColors.sosRed` / SOS-red token introduced anywhere in the new section.

## Decisions Made

- Duplicated the category color/icon mapping as new private top-level functions local to `edit_safe_zone_screen.dart` (matching `safe_zones_screen.dart`'s mapping exactly) rather than importing, since the originals are private to the other file.
- Added a `ValueKey('category-option-<category.name>')` to each `_CategoryOption` so tests can target a specific chip deterministically, per the plan's explicit fallback guidance.
- Fixed the editor test's brittle fixed-offset scroll (`tester.drag` by `-160px`) to `tester.ensureVisible`, since the new card's greater height (icon-led chips + card chrome vs. the old bare `ChoiceChip` `Wrap`) shifted subsequent content down, causing the old hardcoded drag offset to leave the Custom chip under the bottom nav bar / out of the hit-testable viewport.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Editor test's Custom-chip tap failed a hit-test even with the plan's suggested ValueKey fix**
- **Found during:** Task 2 (test verification)
- **Issue:** The plan anticipated that `find.text('Custom')` might resolve ambiguously and recommended adding a `ValueKey` per chip as the fix. After adding the key, the tap still failed with a Flutter hit-test warning (`derived an Offset that would not hit test on the specified widget`) — the real cause was a layout regression: the redesigned card's greater height (icon-led chips with padding vs. the old compact `ChoiceChip` `Wrap`) meant the test's pre-existing fixed `-160px` scroll drag no longer brought the Custom chip fully into the tappable viewport.
- **Fix:** Replaced the fixed-offset `tester.drag` + tap sequence with `tester.ensureVisible(customOption)` before tapping, which is layout-independent and robust to future height changes in the panel.
- **Files modified:** `mobile/test/features/geofencing/safe_zone_editor_test.dart`
- **Verification:** `flutter test test/features/geofencing/safe_zone_editor_test.dart test/features/geofencing/safe_zone_router_flow_test.dart` — all 15 tests pass.
