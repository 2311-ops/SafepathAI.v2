<decisions>
Three points where the brief was ambiguous or self-contradictory. These are resolved — implement as stated.

**D-01 — Extend `SafePathCard`, do not fork it.** The brief says to pass `backgroundColor`/`borderColor` "to the underlying SafePathCard" but that API does not exist (fact 1). Add `Color? color` and `BoxBorder? border`, both defaulting to `null`, resolving to `AppColors.surface` and no border respectively. This keeps all 31 existing call sites pixel-identical and is strictly additive.

**D-02 — Date picker must be normalised to date-only and clamped.** `showDatePicker` **asserts** if `initialDate` falls outside `firstDate`/`lastDate`. `selectedDate` is a UTC midnight, so `selectedDate.toLocal()` in a positive-offset zone is *today at 02:00*, which is greater than a `lastDate` of `DateTime.now()` whenever the user opens the screen before 02:00 local. That is a real crash. Strip all three to date-only (`DateTime(y, m, d)`) and clamp `initialDate` so it can never exceed `lastDate`.

**D-03 — Add an `onDateSelected` callback; do not simulate chevron taps.** The brief offered a choice. Computing a day delta and firing the existing chevron callback N times would issue N network loads for one pick — unacceptable. One new `ValueChanged<DateTime>` field on `_HistoryHeader` plus one new static `_goToDate` on the screen is both smaller and correct. Record this reasoning in the summary, as the brief requests.

**D-04 — The one authorised hardcoded hex.** The brief explicitly specifies `const Color(0xFF1E7A50)` for the duration-badge text. This conflicts with the project's locked-design-system rule, but the value comes from the user-approved mockup and exists for contrast: `AppColors.safe` on `safeBg` is only ~2.6:1, while `0xFF1E7A50` reaches ~4.4:1 at 11.5px. Ship the brief's hex, but keep it as a private `const` **local to `timeline_node.dart`** — do **not** add it to `AppColors`, which stays locked and unmodified. Call this out explicitly in the summary so the user can accept or reject it.
</decisions>
