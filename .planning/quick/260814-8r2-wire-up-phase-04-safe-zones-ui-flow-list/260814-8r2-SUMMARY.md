# Quick Task 260814-8r2: Wire up Phase 04 Safe Zones UI flow Summary

**Connected the four Safe Zones routes to live Riverpod state via new SafeZonesPage/SafeZoneEditorPage/SafeZoneReviewPage/SafeZoneDetailPage wrappers, added an edit-prefill seam, fixed a guardian-recipient reset bug, and added router-level regression coverage driving the real `routerProvider`.**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-08-14
- **Tasks:** 3
- **Files modified:** 7 (3 new, 4 modified)

## Accomplishments
- `/safe-zones` now renders the caller's real safe zones (previously a frozen `SafeZonesScreen.loading()` const) with each card labelled by the assigned member's real display name.
- `/safe-zones/add` now builds the editor with the real family id and member list (previously empty strings/lists, which left "Review zone" permanently disabled).
- New `/safe-zones/add/review` route finally backs `SafeZoneReviewScreen`, reused by both the create and edit journeys since the draft's `zoneId` (not the route) determines create vs. update.
- New `/safe-zones/:zoneId/edit` route finally backs the entry that was already listed in `_authenticatedOnlyRoutes` with no `GoRoute` behind it; it prefills the existing zone via a new `SafeZoneDraft.fromZone` factory so saving issues an `update`, not a `create`.
- `SafeZoneDetailScreen`'s "View activity" button is now wired (reuses the existing `/zone-activity` route).
- Fixed a real bug: `GeofenceController.loadFamily` was unconditionally overwriting `guardianRecipientIds` from `activeGuardianIds` on every call — since both the editor and the review screen call `loadFamily` on mount, reaching review after deliberately narrowing the guardian-recipient selection silently reset it back to every active guardian (a safety-relevant over-notification bug for a family-safety product).
- Added a router-level test suite (`safe_zone_router_flow_test.dart`) driving the real `routerProvider` end-to-end: list rendering with real names, the full create journey (list → add → review → save, asserting the Review button's `onPressed` transitions from null to non-null), and the edit journey (prefill + save-as-update).

## Decisions Made
- Reused the same `/safe-zones/add/review` route for both the create and edit journeys, since `SafeZoneDraft.zoneId` (not the route) is what makes `GeofenceController.save()` choose `update` over `create` — avoids introducing a second save path.
- Wired `SafeZoneDetailScreen`'s "View activity" button in the same pass (in scope per the plan's explicit callout) since it reuses the already-existing `/zone-activity` route at one line of cost.
- Left `SafeZoneDetailScreen.onDeleteConfirmed`/`onOpenSettings` unwired, per the plan's explicit out-of-scope call: `GeofenceListController.deleteZone` already exists but deletion was not part of the reported gap.
