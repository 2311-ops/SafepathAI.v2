<objective>
Wire the Phase 04 Safe Zones screens into the running app. The screens exist and are
unit-tested in isolation, but at the router level `/safe-zones` renders a frozen loading
const, `/safe-zones/add` is constructed with an empty family id and member list (leaving its
Review button permanently disabled), `SafeZoneReviewScreen` has no route at all, and
`/safe-zones/:zoneId/edit` is listed in the auth-guard set with no `GoRoute` behind it.

Purpose: make the guardian-facing safe-zone create/edit journey actually reachable and
functional, and add the router-level coverage that would have caught this class of gap.

Output: one new connected-wrapper file holding four `Page` widgets (matching the existing
`NotificationsPage`/`QuietHoursPage`/`RoutineActivityPage` convention), four corrected
router entries, a minimal edit-prefill seam on the editor screen, and a router-level
integration test.

**In scope beyond the literal gap list** (called out so it is visible, not slipped in):
`SafeZoneDetailScreen`'s "View activity" button is also currently dead and is wired in the
same new `SafeZoneDetailPage` wrapper, because it reuses the already-existing
`/zone-activity` route and costs one line.

**Explicitly out of scope** (left dead, flag for a follow-up if wanted):
`SafeZoneDetailScreen.onDeleteConfirmed` and `onOpenSettings`. `GeofenceListController`
already has a `deleteZone` method, but deletion was not part of the reported gap and adding
it would widen the blast radius of this task.
</objective>

the draft itself carries `zoneId`, which is what makes `GeofenceController.save()` choose
update over create.

`SafeZoneReviewPage` — a `ConsumerWidget`. Same family resolution and null-family fallback.
Return `SafeZoneReviewScreen` with the real `familyId`/`members`, `mapOverride` from the
provider, all five `onEdit*` callbacks wired to `context.pop()` (the editor is directly
beneath on the navigation stack, so popping returns to it with the draft intact), and
`onSaved` that: re-runs `geofenceListControllerProvider.notifier.load(familyId)` so the list
reflects the new or updated zone, then calls `context.go('/safe-zones')` followed by
`context.push('/safe-zones/{zone.id}', extra: zone)` so the user lands on the saved zone's
detail screen with the list as its back target and the add/review pages discarded. If that
two-step navigation misbehaves at runtime, degrade to `context.go('/safe-zones')` alone and
record the deviation in the summary.

`SafeZoneDetailPage` — a `ConsumerWidget` taking `required String zoneId` and `SafeZone? zone`.

`onDeleteConfirmed` unset — out of scope, per the objective.

In `geofence_models.dart`, add a `SafeZoneDraft.fromZone(SafeZone zone, {String? familyId})`
factory that copies `id` into `zoneId` and carries category, name, center, radiusMeters,
assignedMemberId, sensitivity, guardianRecipientIds, and notifyAssignedMember across. This is
what makes an edit save an update.

In `edit_safe_zone_screen.dart`, add an optional `final SafeZone? initialZone;` constructor
param. In the existing `initState` postFrame callback, branch: when `initialZone` is non-null
call `loadDraftForEdit(SafeZoneDraft.fromZone(initialZone, familyId: widget.familyId))`,
otherwise keep the current `loadFamily(...)` call unchanged. Set `_nameController.text` from
`controller.draft.name` after either branch, as it already does. Make the AppBar title read
`'Edit safe zone'` when `initialZone` is non-null and keep `'Add safe zone'` otherwise. Change

In `geofence_controller.dart`, make `loadFamily` non-destructive of an existing recipient

deselected. Leave every other method in the file untouched.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deep link / `extra` → route builder | A `/safe-zones/:zoneId` or `/safe-zones/:zoneId/edit` URL can arrive from a push notification or a cold link with no `extra` payload and an arbitrary `zoneId` string. |
| mobile client → backend geofence API | Every zone read/write crosses to `GeofencesController`, which is the authoritative authorization point (04-06). |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
