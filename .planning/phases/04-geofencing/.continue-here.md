## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Riverpod provider with no reader | `geofenceRegistrationControllerProvider` (04-03) had `build()` logic that auto-syncs on auth state, but nothing in the app ever `ref.read`/`ref.watch`'d it, so it was structurally dead code despite passing unit tests. Fixed via `container.read(...)` in `main.dart` (commit `3153e43`), mirroring the existing `pushServiceControllerProvider`/`quickActionsServiceProvider` pattern. | advisory | When a future plan adds a new startup-sync provider, verify it is actually read from `main.dart` or a live widget — a passing unit test does not prove the provider is ever instantiated in the running app. |
| Small geofence radius unreliable | Google Play Services appears to internally floor the effective monitored geofence radius to ~80m regardless of the configured value — confirmed identical `GeofenceRequest(...+80.0m...)` log output for both a 40m and a 5m test zone. Not a bug in this codebase. | advisory | Any future zone-radius UI/preset work (plan 04-12) should not offer radii meaningfully below ~80-100m as "tight" options without surfacing this platform floor to the user. |
