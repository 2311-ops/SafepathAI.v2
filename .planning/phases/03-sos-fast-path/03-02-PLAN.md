## Phase Goal

**As a** family member in danger, **I want to** trigger an SOS that instantly reaches my guardians and emergency contacts with my live location, **so that** help can find me within seconds even if I have no signal, my phone is locked, or the app is closed.

<objective>
Close the first vertical slice: a real user can now press and hold the raised centre SOS button for three seconds and land in a full-screen emergency session that reports the server received their alert.

Purpose: DESIGN-02 and D-01/D-02 specify this control down to the pixel and millisecond, and the current `_SosTabButton` violates all of it — it is a tab switcher that shows a "Coming soon" snackbar. D-03 requires the post-send destination to be a full-screen emergency session rather than a banner or bottom sheet. D-13/D-14 additionally require the session id to exist on-device before any network call so an offline trigger (plan 03-07) is already the same emergency.

Output: the batch install of every Flutter package this phase needs, the rebuilt press-and-hold SOS control, the `sos` feature module's data/application layer, the full-screen sender emergency session route, and the two mobile Wave 0 test files from `03-VALIDATION.md`.

Scope boundaries inside this phase: the emergency session renders the "Sending alert…" and "Alert active" states here; plan 03-04 adds the per-recipient delivery list, 03-07 adds the offline/retrying state and local fallback actions, 03-08 adds the live-location countdown, 03-09 adds hold-to-cancel and the canceled state. Silent/Duress has no UI surface in any of them (D-28).

This plan owns `mobile/pubspec.yaml` for the whole phase — every later mobile plan uses packages installed here rather than editing the manifest itself.
</objective>
